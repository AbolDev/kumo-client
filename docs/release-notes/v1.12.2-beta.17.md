# Kumo 1.12.2 beta 17 (test version)

This is a test version (pre-release). It is not offered as an update unless *Include pre-releases* is on in Settings.

## What's new since beta 16

- **AmneziaWG servers.** A WireGuard link (`wireguard://`, also `awg://` and `amneziawg://`) or a `.conf` file with the settings of AmneziaWG (`Jc`, `Jmin`, `Jmax`, `S1` to `S4`, `H1` to `H4`, `I1` to `I5`, and the ones of AmneziaWG 3: `RandomTrailers`, `DisableCookies`, `HeaderProtectionKey`, `ContentPaddingAddition` and the times) is a server of its own kind (*amneziawg* in the lists), made so that a filter that knows the packets of WireGuard does not know these.
  - *On Android* the core runs it itself, on the reference `amneziawg-go`. *On a computer* a program of its own, `kumo-awg` (next to `kumo-core`), carries the server and the core sends what is to go through it to that program's local port, as it does for Xray. The AmneziaWG servers are in the automatic group like the others.
  - Read from Amnezia's own app too: its `vpn://` links, the series of QR codes it shows for a server (read part by part with the camera, from a picture or from the screen, and put together), and its settings in Clash (`amnezia-wg-option`) and sing-box subscriptions. A file written as Amnezia writes it (`on` for the flags, the header key in base64, a comment with the name above `[Peer]`) is read.
  - *Edit config* has a section for the settings of AmneziaWG. An import that is refused says which setting it did not accept, in your language. The F-Droid build has the endpoint too.
  - **Tried so far:** on a phone and on Windows in the proxy mode, with a server of AmneziaWG 3. **Not tried yet:** the whole-device mode on a computer, macOS and Linux, the series of QR codes of Amnezia (read from its description of the format, no real code was scanned), and the group with AmneziaWG servers on a computer. If something does not connect, send the log (*Settings > Logs*).

Everything else is as in [beta 1](https://github.com/AbolDev/kumo-client/releases/tag/v1.12.2-beta.1) to beta 16. The WARP server that fails when connected (*wg-noise-a*, *wg-noise-b*) is not fixed yet: if you see it, send the log (*Settings > Logs*) after a few minutes of connection.
