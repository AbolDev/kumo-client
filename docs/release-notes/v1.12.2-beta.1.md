# Kumo 1.12.2 beta 1 (test version)

This is a test version (pre-release). It is not offered as an update unless *Include pre-releases* is on in Settings.

## What's new

- **Crash reports.** If something breaks, Kumo can send a report with the same switch as the anonymous usage count (*Settings > App settings*; off means nothing is queued or sent). It holds the error and where it happened in the code, the Kumo and system version, the device maker and model, the page you were on, whether the VPN was connected and the last lines of Kumo's own log. Links, IP addresses, e-mail addresses, ids, tokens, passwords, the names of your servers and subscriptions, and your user name in folder paths are removed before it is saved or sent. At most 10 a day. The details are in the [privacy policy](https://github.com/AbolDev/kumo-client/blob/main/PRIVACY.md).
- **Open links and files with Kumo.** `vless://`, `vmess://`, `trojan://`, `ss://`, `hysteria2://` and the other server links, subscription links (`clash://`, `sing-box://`, `hiddify://`), shared text and `.json`, `.yaml` and `.ovpn` files can be opened with Kumo from a browser or a chat (on Android also from the *Share* menu). Kumo always asks before it adds anything. On Windows the installer has a task for it (on by default), on Linux the packages list the links, and a copy of Kumo that is already running takes the link. On macOS the system hands them over through the app itself.
- **User-Agent and headers for a subscription.** *Edit subscription > Advanced*: some providers answer only one kind of client or want a key in a header. Headers go only to the subscription's own address and are also used by the background update on Android.
- **Find the best settings for my network** (*Home menu > Troubleshoot*). Kumo tries a few options (splitting the TLS hello, a browser fingerprint, multiplexing) on up to three of your VLESS, VMess or Trojan servers and shows which work best on your network. It applies a better one only when you tap *Use it*, and you can undo it. It runs on your device only and sends nothing. Name lookups (DNS) are not part of it.
- **WARP: find the best way to connect, and Warp-in-Warp.** On the WARP page, *Find the best way* tries every method, address and port of the profile and switches to the fastest one that answers. *Warp-in-Warp* (experimental) carries one WARP tunnel inside a second WARP account's tunnel. *Scan more addresses* also tries addresses from Cloudflare's WARP ranges that are not in the profile.
- **Server names are looked up over encrypted DNS first.** Before it connects, Kumo looks up the name of the server over encrypted DNS (Cloudflare, then Google), so your network's resolver cannot see which server you look for or hand out a wrong address. If those two are blocked, it asks the system's own resolver as before. It is on by default and can be turned off in *Settings > Network*; *Strict DNS* is unchanged. Cloudflare and Google see the server's name.
- **Android kill switch.** With the kill switch on, the internet now stays blocked when the sing-box core stops by itself, or when a reconnect of a connection that was up fails (before, only when Xray stopped).
- **Android Always-on VPN.** When the system starts Kumo itself (*Always-on VPN* in Android's VPN settings), Kumo now connects again with the last connection instead of ignoring the request.
- **Find a clean IP** (*Edit config > Find a clean IP*, for VLESS, VMess and Trojan servers behind a CDN). Kumo tries addresses of Cloudflare, Fastly or ranges you type, with the server's own settings, and shows the fastest ones. It runs on your device only.
- **Usage count.** The maker and model of the device are now sent from every system (before, only Android), and on Linux the desktop. No serial number or computer name is read.
- **A request for a star.** After a week of use Kumo asks once, and at most a second time a month later, whether you would star the project on GitHub. *Don't ask again* ends it.

## Please try and tell us

Most of this was checked by tests, not on every kind of device. We would like to hear how these work for you, especially: opening links and files (Android, macOS, Linux), the Android kill switch and Always-on VPN, the WARP scans and Warp-in-Warp, *Find a clean IP*, and the encrypted name lookup on your network. The log page shows what happened.
