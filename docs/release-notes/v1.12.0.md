# Kumo 1.12.0

## What's new

- **OpenVPN (Windows and Android).** Add an `.ovpn` file (from the **+** menu: *Add from file* or *Add from clipboard*), or take servers from *Free connections > VPN Gate servers*, and connect like any other server.
  - A file is never run as it is. Kumo reads the lines it knows and writes its own configuration; lines that run programs, open a control port, write files or load other files are left out.
  - On Windows Kumo runs the official OpenVPN (signed by OpenVPN Inc.) with the TAP-Windows driver that comes with it; Windows may ask you to confirm the driver once. On Android the official OpenVPN program (2.6.14, with OpenSSL, LZO and LZ4) runs as a service of its own.
  - A login the server asks for is asked in a window; a login the file does not mention can be given there too.
  - *TCP ping* and *Real delay* work for OpenVPN servers on Windows; on Android only the TCP/UDP ping works.
  - On Android sing-box's routing options (bypass lists, ad blocking) do not apply while OpenVPN runs. Per-app routing, the kill switch and the notification with speed work. The tile, the widget and the device-startup receiver open the app instead of connecting an OpenVPN server. *Keep the proxy running* and the automatic mode do not use OpenVPN servers. Old ciphers such as BF-CBC are not supported.
- **VPN Gate servers in Free connections (Windows and Android).** The public OpenVPN servers of [VPN Gate](https://www.vpngate.net). vpngate.net cannot be opened from Iran, so the list is copied every 3 hours to a GitHub repository ([AbolDev/vpngate-mirror](https://github.com/AbolDev/vpngate-mirror)) and Kumo takes it from GitHub and its mirrors. Nothing in the list is filtered, so some servers will not connect. VPN Gate's servers are run by volunteers and may keep logs: do not use them for anything private.
- **Locked `.npvs` files** open in under a second, and a server's settings are no longer lost: the text `"false"` was read as true, and the *final mask*, the socket options and the gRPC timings were dropped. Newer exports whose lines hold a name and a v2rayJson are read too, and each server gets its name.
- **The kept proxy is never closed (desktop).** With *Keep the proxy running* on, Kumo itself listens on the proxy port and passes each connection to the core that runs at that moment, so connecting, disconnecting and changing the server do not close the port. Connections that are going through a core when it stops are still cut.
- **Anonymous usage count.** Once a day (and again when the version changes) Kumo sends a random-looking code made from your device id, plus your system and Kumo version, the app's language and your device's language and country setting, your time zone, your processor, the name of the release file that was installed (for example `kumo-android-universal.apk`), and on Android the phone's maker, model and interface. It never sends servers, links, browsing or traffic, and no IP address is stored. It is on by default and can be turned off in *Settings > App settings*; turning it off sends one last message and then nothing. It is sent in the background and never delays starting or connecting. The details are in the [privacy policy](https://github.com/AbolDev/kumo-client/blob/main/PRIVACY.md).
- **Update check.** Test versions of one release are told apart by their suffix (`beta.10` is newer than `beta.9`), and the stable release is newer than its test versions.
- **Fixes.** *Disconnect* on Windows no longer reconnects at once, and "Disconnecting" can no longer stay for good. The connect button works while OpenVPN is starting. A server that asks for a login its file does not mention now gets the login window. The password window and the number windows in Settings are clearer. The notice on the home screen is no longer stuck to the status above it.

## About OpenVPN

OpenVPN on Android was tried on an emulator against a local server (connecting, traffic through the tunnel, disconnecting, a refused login, a timeout). It has **not** been tried on a phone, on arm CPUs or with a public server. On Windows, one network in Iran cut OpenVPN at the secure handshake for every public server tried; a connection through a real server has not been seen in Kumo. Please report what you see (the log page shows the messages of OpenVPN).
