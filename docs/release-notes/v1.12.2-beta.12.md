# Kumo 1.12.2 beta 12 (test version)

This is a test version (pre-release). It is not offered as an update unless *Include pre-releases* is on in Settings.

## What's new since beta 11

- **WireGuard servers can be tested on Android.** The real delay, the ping, the speed test and the safety check of a WireGuard server ended at once on Android and were shown as a timeout (and, before this version, the safety check and real delay could close the app). The test core had no outbound, so sing-box made a direct one that fails at its start there. The tests now name the WireGuard tunnel as their default. WARP and Warp-in-Warp servers are tested the same way. A test that fails inside the core now ends that test and not the app.
- **A WireGuard server connects with the DNS of its own configuration.** The configuration names the DNS servers to ask through its tunnel (`DNS = 1.1.1.1, 8.8.8.8`). Kumo asked an encrypted DNS server instead, which a server inside Iran often cannot reach, so the connection was up and no name was found. The first DNS server of the configuration is used now when such a server is the only one, unless you typed a DNS server of your own. A `.conf` file keeps its DNS when it is turned into a link.
- **A ping of a whole list no longer calls UDP servers dead.** *TCP ping all servers* tried a TCP connect to WireGuard, Hysteria and TUIC servers, which have no TCP port. With no connection up they are measured through the core now (three at a time). While connected they are left as they were. A ping of one server while connected is taken through the connection.
- **A server that reaches only domestic sites.** When the usual test page cannot be fetched through a server, a page hosted in Iran is tried. A server that gets only that one shows its delay with *domestic sites only*, is not picked by the automatic mode, and keeps being tested this way.
- **The logs say much more.** Every line has a level and a subject (connection, tests, servers, core, app) and a time, and the log keeps 2000 lines. Connecting says the server, its protocol and the mode, and how long it took. A test from a server's menu writes its result, and a failed WireGuard test writes what the core said. What the core says while a connection is made and while it runs is in the log too (how much is the log level of the network settings). The page groups lines by day, filters by problems, details and subject with counts, searches, copies a line with a tap, and asks before it clears. The log has an entry of its own in *Settings* and in *Tools*; it was under *Live connections*.
- **If the core stops the app, the next start says so.** The last words of the core are shown once, with a button to copy them for a bug report.
- **A clearer progress of a list test.** The bar under the name of a group is green for the servers that answered, red for the ones that did not, and empty for the rest, with the three counts under it and a stop button in place of *Cancel*.
- **Pure black dark theme.** The tiles of configs and subscriptions had the colour of the background; they take the colour of the speed cards now.

Everything else is as in [beta 1](https://github.com/AbolDev/kumo-client/releases/tag/v1.12.2-beta.1) to beta 11. Most of it was checked by tests, not on every kind of device (the WireGuard fixes were tried on one Android emulator and on Windows), so please tell us what you see.
