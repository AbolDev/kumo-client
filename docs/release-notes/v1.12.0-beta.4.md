# Kumo 1.12.0 beta 4 (test version)

This is a test version (pre-release). It is not offered as an update unless *Include pre-releases* is on in Settings. **Windows only for the new part.**

## What's new since beta 3

- **The connect button works while OpenVPN is starting.** A tap on it during the minute OpenVPN needs to connect left the screen on "Disconnecting..." for good, with no way out. It now stops the attempt at once, and on the desktop a stop that gets no answer puts the screen back after a few seconds.
- **A clear message when the network blocks OpenVPN.** If the server answers but the secure handshake never finishes, Kumo says that the network is probably blocking OpenVPN (instead of a few lines of log).

## OpenVPN (a test feature, Windows)

- Add an `.ovpn` file (from the **+** menu: *Add from file* or *Add from clipboard*, with the certificates inside the file). It becomes a server of the type *openvpn* in *Added manually*.
- A file is never run as it is. Kumo reads the lines it knows and writes its own configuration; lines that run programs, open a control port, write files or load other files are left out.
- If the server asks for a user name and password, an *OpenVPN login* window opens (also in the menu of the server).
- Kumo runs the official OpenVPN (signed by OpenVPN Inc., with the TAP driver beside it) and sends everything out through its adapter.
- Not yet: Linux, macOS and Android, tests of the servers' delay, and the *keep the proxy running* mode.

## About this test

The adapter and the driver now work, and OpenVPN reaches the server, but on one network in Iran every public server tried (10 of VPN Gate, TCP and UDP) stopped at the secure handshake, also with OpenVPN run alone: that network seems to cut OpenVPN. A real connection has **not yet been seen** in Kumo; please try on another network (for example a mobile operator) and report what you see (the log page shows the messages of OpenVPN).
